Agentic UX Concept

Smart Substitutions & Latency

A fast concept exploring how AI-driven substitution should feel in grocery e-commerce. Designed around latency, trust, and deterministic fallback states.

The Problem

When an item goes out of stock in a grocery order, the default experience is manual: the customer either picks a replacement themselves or gets nothing. If an AI agent takes over that decision, it introduces a new problem: latency while it queries inventory and evaluates alternatives, and a trust gap when it presents a substitution the customer didn't ask for.

The question this concept answers: what does it look like to design for that exact moment? The gap between "item unavailable" and "agent has a recommendation" without it feeling broken, slow, or untrustworthy?

Handling Latency

Frame 1: The "Thinking" State

Instead of a generic loading spinner, the out of stock item shows a progressive loading component: sequential status text ("AI Agent checking local dairy inventory..." → "Evaluating organic alternatives...") paired with a subtle progress indicator.

Why it matters: LLM retrieval takes real time. Abstracting that wait into visible, conversational steps prevents abandonment and builds trust. The user can see the agent is working, not stuck. A small accessibility annotation calls out that these steps update via an aria-live region, ensuring screen reader users aren't left on a silent spinner.

Building Trust

Frame 2: The Agentic Recommendation

The agent presents two substitution options, each with a short rationale tag rather than just a name and price:

  • Natrel Organic 2% Matches Dietary & Brand Tier
  • PC Standard 2% Matches Brand, Lower Price

Why it matters: AI recommendations need to feel deterministic, not magical. Surfacing the reasoning behind each option reduces cognitive load for the customer and cuts down on the support tickets that result from unexplained auto-substitutions.

Graceful Degradation

Frame 3: Constraint & Fallback

"Agentic UX in grocery e-commerce cannot just be a chatbot. It requires deterministic fallback states. If the LLM confidence score for a dietary match is below 95%, the UI must gracefully degrade to a manual search fallback to avoid compliance and health risks."

The actual fallback UI provides a clear "Low Substitution Confidence" message with two ways forward: search manually, or browse alternatives. A low-confidence moment resolves as a graceful next step, not a dead end.

Hypothetical Success Metrics

Acceptance Rate

Achieve >85% substitution acceptance rate by surfacing deterministic rationale chips.

Ticket Reduction

Measurable drop in customer support queries tied directly to unexplained auto-substitutions.

Resolution Time

Decrease average time-to-resolution on out of stock cart items during checkout.

Reflection

The interesting design problem here wasn't the happy path. It was designing for uncertainty. Latency, confidence scores, and failure states are usually treated as engineering concerns that get bolted onto a UI after the fact. Treating them as first-class design decisions. Focusing on what the user sees while the system is unsure, and what happens when it is too unsure to act, is exactly where agentic products either earn trust or lose it.
