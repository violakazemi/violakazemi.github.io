Tomaan

Reimagining Offline Security for the AI-Native Era

Role Product Designer
Status 2026 Concept

Overview

This concept asks a narrow, difficult question: can a real-time AI fraud check sit on top of an offline one-time-password (OTP) system without weakening the one guarantee that makes it trustworthy—that your code never has to travel anywhere to prove who you are?

Context: The Legacy Offline OTP Foundation

At Carrene, I designed the interfaces for offline OTP apps used to protect card transactions for a security-conscious banking user base. Those apps scaled past 2 million users. The core mechanism generated a code entirely offline, valid for 60 seconds. Tomaan explores adding a generative AI judgment layer to this proven system to stop authorized fraud (scams), without ever touching the offline guarantee underneath it.

The UX Challenges of AI Security

Three things are true about generative security checks that weren't true about deterministic offline flows:

Constraint 1

Generative Latency

They're slow relative to user expectation. An LLM fraud check can take seconds. A static loading spinner over that duration reads as "broken," destroying systemic trust.

Constraint 2

Estimate Uncertainty

They're probabilistic. The old flow didn't guess—a code either matched or it didn't. An AI fraud check estimates, and that estimate must be shown clearly.

Constraint 3

Quiet Failures

An AI layer can fail quietly—it can time out, degrade, or hallucinate. The interface needs a way to say "this part of the system isn't sure" without triggering panic.

Design Solutions

I designed three core screens that answer these constraints directly, establishing a highly secure, modern generative paradigm.

01 — Dashboard

Establishing Visual Trust

The dashboard introduces the system's central new primitive before the user ever needs it under pressure: the confidence chip. Placed under the balance, it acts as a low-stakes, ambient exposure to a visual language tied to AI certainty.

Color Conflict Resolution

My first pass used red/green dots for both transaction direction (money in/out) and AI confidence, causing them to collide. I removed color from the debit/credit indicator entirely (using a plain +/− prefix) and reserved red/green exclusively for confidence signaling.

02 — Authorization

Designing for the Wait

When a transfer is initiated, the interface doesn't freeze on a spinner—it shows the bank's model at work. A typewriter-style sequence narrates the check (verifying recipient, cross-referencing patterns) so the user can tell "done" from "in progress" at a glance.

Legibility as a Prerequisite

The sequence resolves into a confidence score (98% Low Risk) before revealing the offline-generated code. The ordering matters: the user sees the bank's reasoning conclude before they see the number they're supposed to trust.

03 — Fallback

Precision Degradation

Most AI concepts stop at the happy path. If a check times out, the interface doesn't declare total failure. It scopes the problem precisely ("Recipient check unavailable") and falls back to the original mechanism: a manually entered, offline OTP.

Why Fallbacks Aren't Errors

The visual treatment stays calm rather than switching to red-alert styling. A fallback to a proven legacy mechanism isn't an error—it's the system working correctly. The "old" mechanism becomes the safety net.

Takeaways & Open Questions

If bringing this into a real production environment, I would resolve these UX risks with the security and engineering teams:

Validation 1

Alert Fatigue

Confidence indicators need to earn their visibility. If every transaction shows a badge, users stop reading them. We need usage data to decide how often to surface the chip versus staying silent.

Validation 2

The Missing Middle

This designs the happy path and the timeout path. The missing state is genuine uncertainty. My proposal: a distinct screen requiring a slow-press hold confirmation, naming specific doubts in plain language.

Note: Tomaan is a personal design exploration, not a shipped product. It builds on real work I did at Carrene designing offline OTP interfaces for a security-conscious banking user base.
