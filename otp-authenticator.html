Maple Trust Mobile Token

A native app that makes one-time passwords for card payments. Each code lasts only 60 seconds. I designed a countdown ring that turns red in the last 5 seconds, so a payment doesn’t fail because the code ran out halfway.

RoleUI/UX Designer
CompanyCarrene Corp
Timeline2021 – 2024
PlatformsiOS & Android

My part: I was the only designer when the app started. I designed its screens and flows for iOS and Android.

Note: I rebuilt these screens to share them here. The flows and decisions are real.

The short version

People needed a code to approve a card payment. Often at a card reader or at checkout, in a hurry. The code lived on the phone, worked offline and expired in 60 seconds. My job was to make it fast to find, easy to read and hard to miss when time ran out.

The problem

The bank was replacing a fixed card password with codes that change. A fixed password can be stolen once and used again and again. A code that changes every 60 seconds can’t. A new rule made these codes required for online card payments. And a new code every time asks more of people, so the app had to make it easy.

Pain point 1

No internet all the time

Many of our users didn’t have internet all the time. But they still needed a code to pay.

Pain point 2

Codes used on the spot

Most codes were used at ATMs and card readers in stores. People were standing up, often with a line behind them.

Pain point 3

A new habit

People knew their fixed password by heart. Now they needed a new code every time they paid.

A typical moment: someone is at a store card reader with a line behind them. They open the app, pick Password 1 and type 4 digits. If the code runs out halfway, the payment fails and they start again.

Two kinds of password

Each card could have two passwords, for two kinds of payment:

Password 1 · 4 digits

ATMs and card readers

Like taking out cash, or paying in a store.

Password 2 · 6 digits

Online shopping and transactions

For paying or moving money online.

Constraints

Every design choice had to fit inside these.

Works offline

After you register, codes are made on the phone, with no internet.

60 seconds max

The bank’s security limit for each code.

Ring library limits

The ring couldn’t change size without bugs, so it stayed one fixed size on every screen.

iOS and Android

Followed Apple’s guidelines and Material Design.

Setup: ATM, then SMS

People activated at the bank’s ATM first, then confirmed with a code by SMS. The bank owned the ATM step and didn’t approve email.

App password reset only at an ATM

If someone forgot their app password, they had to reset it at an ATM. A security rule from the bank.

The core flow

People first activated at the bank’s ATM. Then it took three steps in the app, from signing up to paying.

Step 1

Sign up

People enter their phone number. The app sends an activation code to it by SMS.

Step 2

Activate

They type the code from the SMS before the timer runs out.

Step 3

Use a password

Swipe to the card, pick Password 1 or 2 and copy the code. The big ring shows how many seconds are left.

Try it

Red alone wasn’t enough

In the first version, the ring only turned red in the last 5 seconds. Then we thought about people who are color-blind. For them, the change to red was easy to miss. So we added motion: in the last 5 seconds, the ring pulses. Now the warning works even without color.

Each code here starts at 12 seconds, so you don’t wait a full minute.

How I made this demo accessible

  • The switches and the copy buttons work with a keyboard, and each has a clear label.
  • Screen readers hear “5 seconds left” once, not a number every second.
  • If your device is set to reduce motion, the ring still beats, but it fades in and out instead of growing.

Product decisions

Proposed · Not shipped

Activation without a SIM card

The activation code only came by SMS. So I asked: what if someone has internet but no signal? Or no SIM card, like on an iPad?

Options: SMS only, which was the default. Or SMS plus email. Email was my idea.

Why email: people with no signal or no SIM could still activate their passwords.

Trade-off: reach vs. security. Email reaches more people. But the banks’ security teams didn’t accept email as a safe way to verify someone. So we kept SMS only.

Shipped · Changed after testing

30 seconds → 60 seconds

We first launched the app to about 100 bank employees, to get feedback before real customers. In that version, each code worked for 30 seconds. Their feedback: at ATMs and card readers, they often ran out of time before they finished typing.

What we changed: we extended each code to 60 seconds before the public launch.

Trade-off: a longer code is open a little longer. But a code that expires mid-typing fails the person and the payment. 60 seconds was the most the banks’ security team allowed, so we used all of it.

Clarity

One card per bank

Each card only shows the passwords the user turned on. If Password 2 is off, you see a dashed “Add” button, not an empty field. So the screen never shows a code that doesn’t exist.

What I tried: a separate screen for each bank. I dropped it. Many people have cards from more than one bank, and switching screens while a code runs out only adds stress.

Time pressure

Expiry you can read at a glance

In the Maple Trust app, a ring shows the seconds left, as a number. In the multi-bank app, each bank card shows the seconds as text. In both, the last 5 seconds turn red. The number is always there, so the warning doesn’t depend on color only.

Why two styles: the ring came first, in the Maple Trust app. The bank approved it, and it became one of the things people knew their app for. Later we found the ring’s library had limits: changing its size caused bugs. So for the multi-bank app, we proposed a text timer instead.

Speed

Big digits, one-tap copy

People read the code at a card reader, or paste it at checkout. Usually in a hurry. So the digits are big, and the copy button is right next to the code.

What I tried: copying the code automatically when the app opens. It doesn’t work. Some people need both Password 1 and Password 2, so the app can’t know which one to copy.

Security

Lock the app, not just the phone

The app has its own lock, a pattern or a password. Users can also set when it locks. So even if the phone is unlocked, the card passwords stay safe.

Help one tap away

Lost a card? Password not working? Each bank’s support number is there with a call button. Users can also report a problem with the app.
