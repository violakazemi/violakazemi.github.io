The short version

People needed a code to approve a card payment. Often at a card reader or at checkout, in a hurry. The code lived on the phone, worked offline and expired in 60 seconds. My job was to make it fast to find, easy to read and hard to miss when time ran out.

Overview

People needed a one-time password to approve card payments. The app made these passwords on the phone itself. It didn’t need internet. Each code worked for 60 seconds. Each bank could give two kinds of password:

Password 1 · 4 digits

ATMs and card readers

Like taking out cash, or paying in a store.

Password 2 · 6 digits

Online shopping and transactions

For paying or moving money online.

My role

I designed the flows and screens for iOS and Android. I followed Apple’s guidelines and Material Design.

The core flow

Three steps in the multi-bank app, from installing it to paying. The Maple Trust app skips Step 1: it already knows the bank, so it registers by phone.

Step 1

Add a bank

The user picks their bank. Then they scan the code they got from their branch or internet banking.

Step 2

Activate passwords

They pick Password 1, Password 2, or both. Then they enter the activation code from the SMS.

Step 3

Use a password

Each bank has one card. It shows the active passwords, the time left and a copy button.

The password card, live

Product decisions

Proposed · Not shipped

Activation without a SIM card

The activation code only came by SMS. So I asked: what if someone has internet but no signal? Or no SIM card, like on an iPad?

Options: SMS only, which was the default. Or SMS plus email. Email was my idea.

Why email: people with no signal or no SIM could still activate their passwords.

Trade-off: reach vs. security. Email reaches more people. But the banks’ security teams didn’t accept email as a safe way to verify someone. So we kept SMS only.

Clarity

One card per bank

Each card only shows the passwords the user turned on. If Password 2 is off, you see a dashed “Add” button, not an empty field. So the screen never shows a code that doesn’t exist.

Time pressure

Expiry you can read at a glance

A ring shows the seconds left, as a number. In the last 5 seconds it turns red. The number is always there, so the warning doesn’t depend on color only.

Speed

Big digits, one-tap copy

People read the code at a card reader, or paste it at checkout. Usually in a hurry. So the digits are big, and the copy button is right next to the code.

Security

Lock the app, not just the phone

The app has its own lock, a pattern or a password. Users can also set when it locks. So even if the phone is unlocked, the card passwords stay safe.

Help one tap away

Lost a card? Password not working? Each bank’s support number is there with a call button. Users can also report a problem with the app.
