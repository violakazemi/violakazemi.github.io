Concept Overview

IBM watsonx Prompt Lab is an enterprise playground for engineering, testing, and refining model prompts. This proposal introduces a side-by-side Compare View that lets users run and compare multiple variations of prompts, models, and parameters concurrently in a single dashboard layout.

To ensure high compliance and seamless integration, the entire concept is built utilizing strict Carbon Design System constraints, serving as an exercise in extending IBM's corporate UI language. This is a self-directed design proposal, not an IBM-commissioned project.

The Problem

Based on reasoned observation of watsonx Prompt Lab, the current layout restricts testing to a single active editor workspace. Users can only test one prompt variation, one LLM model, and one set of parameters (such as temperature or token limits) at a time.

To compare results across 2 or 3 models or prompt adjustments, users must perform a manual mental-note workflow: edit the prompt, run the test, record the output token counts and responses, select a different model, overwrite the prompt, and run it again. This manual repetition increases friction for a tool whose core enterprise purpose is iterative experimentation.

Proposed Solution: Compare View

We propose a tabbed comparing framework that splits the single workspace canvas into a responsive grid. This allows users to execute concurrent prompts and compare outcomes side-by-side.

Feature 1

Compare Toggles

Switches the single editor panel into 2 or 3 side-by-side pane editors mapped cleanly onto a responsive Carbon 16-Column Grid.

Feature 2

Independent Panes

Each pane houses its own prompt text editor, filterable dropdown model selector, and collapsible parameters side panel.

Feature 3

Unified Run Trigger

A single "Run All" action runs all workspace inputs concurrently to guarantee a synchronous performance and latency benchmark.

Feature 4

Inline Output Rows

Renders generated text output, execution times, and calculated token consumption directly beneath each pane without extra hover details.

Feature 5

Select & Continue

A simple check action lets users select the best performing variation, collapsing the workspace back to single editor mode with the chosen prompt preloaded.

System Alignment & Value

Proposing new interfaces within enterprise environments requires careful alignment with existing component libraries rather than creating custom visual patterns. This concept is built using standard Carbon components:

  • Grid: Manages responsive 2-column or 3-column layouts across desktop screen sizes.
  • Tabs: Switches viewports from single editor workspaces to structured comparison panels.
  • Data Table: Formats inline output comparisons, execution latency, and token consumption metrics.
  • Side Panel: Slides open to configure temperature, stop sequences, and top-p limits on a per-pane basis.

enterprise design systems & data-dense UI

Designing inside a strict, pre-defined design system without breaking its corporate guidelines is a different skill from building freeform apps. Enterprise interfaces require high data-density and strict consistency across desktop dashboards, terminal outputs, and system settings.

This design exercise demonstrates my ability to tackle complex, information-dense layouts within constrained design parameters — exactly the kind of systems challenges faced when building scalable fintech dashboards and multi-surface applications for companies like Indigo.
